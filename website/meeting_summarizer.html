    01 / Overview & Capabilities

    Offline transcription post-processor. Distills meeting transcripts into action trackers, schedules, and bulleted logs with strict formatting rules.

    Key Features

    • Turns conversational text blocks into formal action tables
    • Identifies speaker intent, decisions, and deadlines
    • Map-Reduce pipeline support for 2-hour long transcription logs
    • Strict template outputs matching markdown specifications

    03 / 10-Plane Pure-CPU Harness Integration (slm_harness)

    Rather than executing as an isolated prompt wrapper, SLM Meeting Summarizer is natively orchestrated by the SLMAgents 2.0 10-Plane Pure-CPU Harness (via slm_harness.runtime.legacy_bridge and CascadeRouter). Every call benefits from hybrid llama.cpp GGUF (Q4_K_M) + Quantized INT4/INT8 CPU execution, watermarked LRU memory governance, grammar-constrained decoding, and deterministic verification at $0 API cost:

    Harness PlaneSubsystemHow It Powers SLM Meeting Summarizer on Pure CPU
    Plane 6 CascadeRouter (<35ms) Stage 1 (Transcript / Diarization Speaker Tag Inspection) & Stage 3 (Embedding Margin)
    Plane 2 & 5 MemoryArena & Hybrid CPU Runtime Specialist Role: stt (Whisper-tiny/base INT8) + primary (Qwen3-4B GGUF Q4_K_M). Managed inside Watermark LRU MemoryArena (lite 2.6 GB / balanced 4.7 GB / power 8.2 GB) with zero-copy session sharing and automatic OOM tier step-down (8B -> 4B -> 3B -> 0.8B).
    Plane 7 & 8 Deterministic Verifier & Governance Plane 2 GBNF Action-Item / Owner / Deadline Schema + Plane 3 Sliding-Window Context Compressor
    Plane 1, 3 & 4 Kernel, Artifact Scratchpad & 4-Tier Memory SQLite WAL CheckpointStore (/fork, /rewind, /undo), content-addressed artifact://<sha12> handles to prevent prompt bloat, and hybrid SQLite FTS5 BM25 + HNSW vector memory.

    05 / Configuration & API Reference

    Constructor Parameters

    Instantiate SLMMeetingSummarizer with performance options:

    ParameterType / DefaultDescription
    model_pathstr | NoneExplicit path to GGUF (Q4_K_M) or quantized ONNX model weights. If omitted, managed automatically by the 10-Plane Harness MemoryArena.
    cache_dirstr | NoneDirectory to store model weights offline. Defaults to ~/.cache/slm-meeting/. Also settable via SLM_MEETING_SUMMARIZER_CACHE_DIR.
    n_threadsint | 4CPU thread count for 10-Plane Harness inference (auto-tuned to physical P-cores). Optimize for CPU core count. Also settable via SLM_MEETING_SUMMARIZER_N_THREADS.

    Methods

    Method SignatureReturn TypeDescription
    summarize_transcript(transcript_text, system_prompt=None, user_input=None)dictGroups speakers, extracts decisions, and renders action items into strict Markdown tables.

    Method Parameters (Execution Customization)

    All main execution methods accept optional system routing parameters:

    ParameterType / DefaultDescription
    system_promptstr | NoneOptional custom system prompt instruction to override the default system template response parameters.
    user_inputstr | NoneOptional additional user-supplied target text variables or contextual keys.

    Quick Start

    from slm_meeting import SLMMeetingSummarizer

summarizer = SLMMeetingSummarizer()
todos = summarizer.summarize_transcript(
    transcript_text,
    system_prompt="Extract action items only",
    user_input="Deadline format: YYYY-MM-DD"
)
print(todos)

    Environment Variables

    Configure agent parameters globally using environment values:

    Environment VariableDefaultPurpose
    SLM_MEETING_SUMMARIZER_N_THREADS4Sets CPU inference execution threads.
    SLM_MEETING_SUMMARIZER_CACHE_DIR~/.cache/slm-meeting/Default directory to store local GGUF (Q4_K_M) and quantized INT4/INT8 model weights (shared with ~/.slm_harness/models).

    CPU Performance Tuning

    To run the SLMMeetingSummarizer engine efficiently on CPU under 1.5 GB memory footprint:

    • Match Threads to Core Count: Set n_threads or SLM_MEETING_SUMMARIZER_N_THREADS to match the physical CPU core count.
    • Sequential Processing: Avoid concurrent processing when batch files are large.
    • Garbage Collection: Clear variables and run gc.collect() to release model RAM blocks after execution.
